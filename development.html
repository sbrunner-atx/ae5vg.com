Why this is open source, and what kind of help matters

Everything here was built at one bench, with one rig, one switch and one contest weekend. That is enough to prove a design and nowhere near enough to trust it. The help that matters is not code, mostly: it is running the software somewhere this bench cannot reach, an operating system that has not been tried, a rig family that follows a different manual, a band at a different hour, and writing down what happened.

How to contribute on GitHub

git clone https://github.com/sbrunner-atx/<repo>.git
cd <repo> && uv sync
uv run ruff check .
uv run pytest

Fork, branch, pull request; open an issue first for anything larger than a fix. Each repository carries a CONTRIBUTING.md. The test suites run without a radio, an fldigi or an N3FJP. Licenses per repository: fldigi-mcp is GPL-3.0-or-later, the same as fldigi; the others are MIT.

The model we are building

The long-term goal is on the product page: a small model that reads a digital-mode QSO through noise, running in the field beside fldigi. The pieces that exist today are deterministic, deliberately.

qso-resolver: the deterministic half

  • The reference layer is looked up, never learned: all 85 ARRL and RAC sections plus the Field Day pseudo-section DX, the class grammar, the ITA2 lost-shift table for RTTY, and MASTER.SCP fetched at build time.
  • The resolver is edit-distance against that reference, with no model in the path. Its three deliberate properties: no model, no network and no weights, so the baseline is a floor; confidence is the weakest field, not the average, because one wrong field is a wrong QSO; and ambiguity is never resolved by picking one, because a wrong QSO in the log is worse than a missed one.
  • The evaluation harness prints null instead of a rate until a real held-out set of QSOs exists. A synthetic score presented as accuracy would be exactly what this project exists to be better than.
  • The adapters read ADIF, Cabrillo and fldigi text capture, and pair received lines with logged truth by timestamp.

qso-mcp: the model's interface

  • Two modes on one base model: contest mode with a LoRA adapter over a closed output space, rag-chew mode without it.
  • Confidence is the weakest field: below the threshold the answer is needs_human, and ambiguity is handed back, never guessed.
  • The grammar constraint keeps contest output inside the exchange vocabulary.

What a contribution of real pairs looks like

Turn fldigi's text capture on during a contest, keep the contest log, and send both, with your permission to use them. What your screen showed against what the log says was sent is exactly a training pair. The capture rig's own collection reports on the dashboard. Offers by GitHub issue or by email below.
