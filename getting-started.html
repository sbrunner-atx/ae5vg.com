What you are installing

Claude is an assistant. It runs in the Claude Desktop app, which looks like a messaging window. The two MCP servers are rig-interface cables: one plugs Claude into fldigi, the other into N3FJP. You type plain English; nothing about your fldigi or N3FJP setup changes.

Set up once

  1. Install Claude Desktop from claude.ai/download and sign in. A paid plan is recommended; the free tier can run out of messages mid-QSO.
  2. Start fldigi. Its XML-RPC interface is on by default at 127.0.0.1:7362.
  3. For logging, start N3FJP and enable Settings → Application Program Interface → TCP API Enabled (port 1100).

Load the MCP servers

  1. Download fldigi-mcp.mcpb and n3fjp-mcp.mcpb from Downloads.
  2. In Claude Desktop: Settings → Extensions → Advanced settings → Install Extension, choose the file.
  3. Enter your callsign in the fldigi-mcp settings. It is the transmit gate; blank keeps the station receive-only.
  4. Repeat for n3fjp-mcp. Host and port default to 127.0.0.1:1100.

No terminal, no Python: Claude Desktop's runtime supplies both.

For Claude Code, Cowork and other MCP clients, run the connector from PyPI with uvx fldigi-mcp. Set the variables FLDIGI_HOST, FLDIGI_PORT and FLDIGI_CALLSIGN. To run it from source instead, use this config block:

{
  "mcpServers": {
    "fldigi": {
      "command": "uv",
      "args": ["--directory", "/absolute/path/to/fldigi-mcp", "run", "fldigi-mcp"],
      "env": { "FLDIGI_CALLSIGN": "AE5VG" }
    }
  }
}

Then copy the skill directories (skills/<name>/) into ~/.claude/skills/, or a project's .claude/skills/.

Start a session

Open a new chat, or a Cowork session, and type: What is the fldigi status? Mode, frequency and T/R state come back. If not, run the fldigi diagnostics tells you whether it is a network problem before you blame fldigi.

Your first QSO, on a dummy load

This keys the transmitter: you are the control operator

With the radio on a dummy load, type: Call CQ Field Day until someone answers. Work them, our exchange is 2A STX, log the contact to N3FJP, then keep calling. Watch one full cycle: the TX drop, the listen window, the log entry. Then connect the antenna. stop works at any moment. Under Part 97 you remain the control operator; stay at the station while it transmits.

Hunting for a station

signal_hunt taps the audio fldigi listens to, names each signal's mode from its shape (RTTY, CW, BPSK31/63/125, Olivia, MFSK16, DominoEX, MT63), ranks the station that sits still and calls CQ, and tunes to it. It needs the fldigi-mcp[hunt] extra (numpy, sounddevice); the .mcpb runtime installs it for you. Set Audio input device to the device fldigi uses; part of its name is enough, for example iMic. macOS asks once for microphone permission. Type: Find me someone calling CQ on 20 meters PSK31.

In a Cowork session, a container, or with fldigi on another computer, the server cannot open the sound card. Run fldigi-mcp-tap --device iMic beside fldigi and set Signal-hunt tap URL to http://127.0.0.1:7365, or that computer's address. With no audio at all, signal_hunt with method="api" steps fldigi's own search_up: slow, and blind to mode.

Two more ways to hunt need a patched fldigi. signal_hunt method="browser" reads fldigi's Signal Browser: up to 30 PSK, RTTY or CW stations at once, with their text. The rsid tool lists the RSID bursts fldigi heard, by mode and frequency, without switching the modem.

Proposed, not yet in fldigi

The Signal Browser and RSID patches were offered to the fldigi maintainer on 11 and 16 September 2026 (w1hkj/fldigi issue 55). Neither is merged. On an unpatched fldigi both tools answer with a hint and nothing else changes.

Limits, stated: mode naming is verified on five recordings of known mode, 5 of 5. The hunt is receive only.

fldigi or N3FJP on another computer

For fldigi, start it on the other computer with --xmlrpc-server-address 0.0.0.0 so it accepts LAN connections. Claude Desktop's sandbox reaches only 127.0.0.1. Install mcp-host-bridge on the computer that runs Claude, run one command, and leave the connector host at 127.0.0.1. Trusted LAN only.

mcp-host-bridge install n3fjp --to 192.168.1.50

The same works for fldigi and wsjtx. Keep the link on a trusted LAN or tunnel it over SSH; the connection is not encrypted and fldigi's XML-RPC interface is unauthenticated.
