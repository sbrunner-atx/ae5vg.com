Product · in development

A small language model for digital-mode QSOs

A contest exchange rarely arrives clean. It comes through band noise, fading, and another station transmitting over the top. An experienced operator still reads it, because the vocabulary is closed. The goal: FT8-style reliability of exchange on any keyboard mode, with a model small enough to run beside fldigi on a CPU.

Three principles

01 · Reference layer

Looked up, never learned

All 85 ARRL and RAC sections plus the Field Day pseudo-section DX, the class grammar, the ITA2 lost-shift table, MASTER.SCP fetched at build time. The model cannot invent a section that does not exist, because sections are not something it predicts.

02 · Training data

Real copy, not synthetic

Training pairs come from real received copy: stations recorded through public KiwiSDR receivers sending the same thing more than once, or copied by two Signal Browser channels, with W1AW bulletins and DWD weather RTTY as further sources. The clean side of each pair is inferred from the best copy, not from published text, so the pairs train the model; they do not measure it. Contributed material is tracked with permission.

03 · Evaluation

Honest numbers

The harness runs against a held-out set of real QSOs, which does not yet exist in sufficient size. Until it does, no accuracy percentage is published, synthetic or otherwise.

Two modes on one base model

Contest mode runs a LoRA adapter over a closed output space: the exchange grammar constrains what the model may emit, so a busted section becomes a near-neighbor lookup, not a hallucination. Rag-chew mode runs without the adapter for free text. In both, confidence is the weakest field: when the model is not sure, ambiguity is handed back as needs_human, never guessed.

Status · September 2026

The deterministic half is built: the reference layer, an edit-distance resolver with no model in the path, and the evaluation harness, which prints null instead of a rate until a real held-out set exists. A capture rig runs unattended collecting pairs; its dashboard is public. The model is not trained yet. The code is not public until there is a number to stand behind.

How to help

If you enable text capture in fldigi during a contest and keep your log, you have exactly the pairs this needs: what your screen showed against what the log says was sent. What a contribution looks like, and where to send it, is on the Development page.
