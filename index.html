Amateur radio · digital modes · open source

An AI assistant that can work the bands with you.

Three small connectors put fldigi, WSJT-X and N3FJP under the control of an assistant such as Claude, through the Model Context Protocol. Say "find me someone calling CQ on 20 metres and work them", and it tunes, reads, replies and logs. A Field Guide writes down how to operate that way without embarrassing yourself on the air. And a small language model, still in the making, is learning to read a contest exchange through the noise the way an experienced operator does.

See the software GitHub

Software

Each connector is an MCP server: a small Python program that speaks the radio application's own control protocol on one side and the Model Context Protocol on the other. Install it in Claude Desktop, type your callsign, and the assistant can see and drive the program. Without a callsign every one of them is receive-only; nothing can key a transmitter.

Operate · fldigi

fldigi-mcp

The whole of fldigi's XML-RPC interface, all 174 methods, as a handful of grouped tools: modem, frequency, rig, log, text, transmit. Adds signal hunting, which names each signal in the receiver audio from its shape, ranks the station calling CQ, and tunes to it; and reads fldigi's Signal Browser, every station the decoder bank has locked to, through a patch offered upstream.

Operate · WSJT-X

wsjtx-mcp

FT8, FT4, JT65, MSK144, Q65 and WSPR through WSJT-X's UDP message protocol. The assistant reads every decode in the cycle, picks a station, replies, and follows the exchange through to the logged contact. The weak-signal leg of the trio.

Log · N3FJP

n3fjp-mcp

Logging to Amateur Contact Log and the hundred-plus N3FJP contest loggers over their shared TCP API. Log a contact in one call, run a dupe check, read the log back, set band and mode. Written against the protocol directly, no third-party wrapper.

One shape, three programs

Operate with fldigi-mcp or wsjtx-mcp, log with n3fjp-mcp. The connectors know nothing about each other; the assistant carries the QSO from one to the next. That separation is deliberate: each program's protocol is small, documented, and testable on its own.

Operating Field Guide

Software that can key a transmitter needs operating discipline written down. The Field Guide is that document: three skills an assistant follows on the air, worked examples from Field Day, and the special cases that trip up new operators, human or otherwise.

SkillWhat it governsWhat you get
fldigi-operatingKeying the transmitter, returning to receive the instant an over ends, never ignoring a caller, identifying on schedule.Instant TX-to-RX handoff and a caller never missed.
contest-operatingThe QSO state machine from CQ to logged contact, the special-case playbook, and verified N3FJP logging.Completed exchanges and a clean, duplicate-free log.
signal-huntingNaming each signal's mode from the audio, ranking the station that sits still and calls CQ, tuning to it, confirming in twenty seconds.The right station found, named and tuned before you call.

The model

A contest exchange rarely arrives clean. It comes through band noise, fading, and another station transmitting over the top. An experienced operator still reads it, because the vocabulary is closed: there are 86 legal section tokens, a small set of classes, and callsigns follow a pattern. The project is a small language model that reads the way that operator does, for any keyboard digital mode, the way FT8 already does for one.

Reference layer

Look up, never learn

ARRL and RAC sections, Field Day classes, callsign structure and the contest exchange grammar are closed vocabularies. They are looked up, not learned, so the model cannot invent a section that does not exist.

Real copy, not synthetic

Off-air pairs

Training data is real received text paired with what was actually sent: W1AW bulletins against their published text, weather RTTY against the same, and repeated CQ loops recorded from public KiwiSDR receivers where the best copy stands in for the truth. Every recording is our own, of the public airwaves, and marked as such.

Honest numbers

No accuracy claim yet

The evaluation harness runs against a held-out set of real QSOs that does not exist yet in sufficient size. Until it does, no percentage is published, synthetic or otherwise. A synthetic score presented as accuracy would be exactly what this project exists to be better than.

Status · September 2026

The deterministic half is built: reference layer, an edit-distance resolver with no model in the path, and the harness. The capture rig runs unattended, collecting pairs. The model itself is not trained yet. The code is not public until there is a number to stand behind.
